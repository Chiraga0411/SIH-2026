# Sovereign Workbench — SIH26117

An air-gapped, on-prem AI workbench: local models, local knowledge base, sandboxed
code execution, document workflows with a human approval gate, and a hash-chained
audit trail. This bundle contains the **complete frontend and backend, wired
together**.

```
final/
├── backend/     Node/Express gateway (the whole AI backend — port 4000)
├── frontend/    React + Vite UI (dev 5173, preview 4173)
├── start-backend.cmd      (Windows) starts the gateway
├── start-frontend.cmd     (Windows) starts the UI dev server
├── start-backend.sh       (macOS/Linux) starts the gateway
├── start-frontend.sh      (macOS/Linux) starts the UI dev server
└── README.md               this file
```

## Quick start

Requirements: **Node.js 18+** (tested on Node 22). Optional: Docker Desktop
(enable it for full `--network none` sandbox isolation), `nvidia-smi`
(GPU telemetry), `pdftotext`/`tesseract` (local OCR — the app degrades
honestly without them).

```bash
# 1. backend
cd backend
npm install
npm start                 # gateway on http://127.0.0.1:4000

# 2. frontend (new terminal)
cd frontend
npm install
npm run dev               # UI on http://localhost:5173
```

Open **http://localhost:5173**, sign in as **Engineer / Manager / Admin**
(three local demo accounts with different roles and clearances).

To verify everything end-to-end (35 checks) with the gateway running:

```bash
cd backend && npm run smoke
```

To verify every UI page mounts against the live gateway:

```bash
cd frontend && npm install --no-save happy-dom && node scripts/render_test.mjs
```

## How the two halves are wired

| Concern | Wire |
|---|---|
| Dev/preview proxy | `frontend/vite.config.js` forwards `/api` + `/health` → `127.0.0.1:4000` |
| Other hosts | build with `VITE_API_BASE=http://<server>:4000` (see `frontend/.env.example`) |
| Identity | every request carries `x-demo-user`; the gateway resolves role + clearance |
| Artifacts | UI downloads deliverables through authenticated fetch-blob (`src/api/client.js`) |
| Live data | `src/api/useApi.js` hook — fetch, poll, reload; no mock arrays in pages |

There is **no mock data path in the UI for system state**: models, tasks, traces,
knowledge, audit, queue, evaluation, sovereignty counters and runs are all read
from the gateway. Only explicitly-labelled baseline/reference figures (charts
that say "baseline") come from `src/data/mock.js`.

## Demo script (5 minutes)

1. **Login as Engineer.** Header monitor shows `0` external connections.
2. **Agent panel → Attach file → Run task.** Watch plan/trace fill in live:
   extract → knowledge search (citations) → verify → deliver, with the router's
   *reason* shown ("…routed to Llama-3.2-11B-Vision").
3. **Try to approve as Engineer** → blocked (RBAC). **Sign out, sign in as
   Manager, Agent → Approve and sign** → recorded in the audit chain.
4. **Download Word / Excel / PPT** — real `.docx`, `.xlsx` (live formulas),
   `.pptx` generated by the gateway.
5. **Knowledge panel** as Engineer: ask about the restricted correspondence →
   *"Not found in the knowledge base"* + "2 documents above your clearance were
   not searched". Sign in as Manager → same question, cited answer. Clearance
   is enforced inside the query, not the UI.
6. **Models panel → Hot-add a model** — appended to the registry, routable with
   no restart; every routing decision logs its reason.
7. **Sandbox panel → Run in sandbox** (Python in Docker `--network none`, or an
   isolated local fallback that *says so*), then **Run egress probe** → blocked
   and written to the chain.
8. **Sovereignty → Try an outbound call** → counters stay at 0, attempt logged.
9. **Audit → Verify chain integrity** → every hash recomputed from genesis.
10. **Multimodal → Upload a drawing/scan** → tags extracted and cross-checked
    against the knowledge base (`match / missing / mismatch` per tag), exportable
    to a real Excel workbook.
11. **Evaluation → Re-run harness** → task success recomputed from *live* runs.

## What is real vs. labelled baseline

Real (computed at runtime): model registry + capability routing + routing log,
task plans/traces/timings, file extraction + injection screen, AES-256-GCM
encryption at rest, knowledge retrieval + clearance filter + abstention,
P&ID tag cross-check, sandbox execution + probes + calculations, docx/xlsx/pptx
generation with SHA-256, approval RBAC, hash-chained audit + verification,
projects/queue/activity, GPU telemetry (when `nvidia-smi` exists).

Labelled baseline (marked in the UI as "baseline"): retrieval hit-rate rows
(fixed 30-question set), tasks/day trend, task-mix donut — until the harness is
re-run against a live corpus.

Honest degradation (the UI says which, never overclaims): Docker absent →
sandbox runs in an isolated local process and the panel shows
`FALLBACK (host network)`; `pdftotext`/`tesseract` absent → extraction flags a
REVISE step and labels figures as sample values; no `nvidia-smi` → GPU cells
show "no telemetry" instead of fake numbers.

## Data & privacy

Everything persists to `backend/storage/` (JSON store, uploads, artifacts) —
uploads are encrypted at rest (AES-256-GCM, key in `storage/secret.key`), the
gateway holds no outbound client, and egress policy is `DENY_ALL`. Delete
`backend/storage/` to reset to a clean demo.
